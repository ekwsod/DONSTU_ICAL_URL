# Настройка репозитория

## Секреты

Settings → Secrets and variables → Actions:

| Секрет | Обязателен | Назначение |
|---|---|---|
| `DONSTU_ICAL_URL` | да | ссылка на iCal-календарь группы |
| `BOT_PUSH_URL` | нет | `https://<worker>.workers.dev/push`; без него пары боту не отправляются |
| `BOT_PUSH_TOKEN` | нет | то же значение, что секрет `PUSH_TOKEN` у Worker |

Как получить значения для бота — в [bot/README.md](../bot/README.md).

## GitHub Pages

Settings → Pages → Build and deployment → Source: **GitHub Actions**.

## Права Actions

Каждый workflow сам объявляет нужные права в блоке `permissions`, поэтому в Settings → Actions → General → Workflow permissions достаточно «Read repository contents and packages permissions». Право на запись в репозиторий больше не требуется: прежняя версия keepalive делала технические коммиты, текущая — нет.

## Первый запуск

1. Actions → Schedule Alarm Pages → Run workflow (ветка `main`).
2. Откройте `https://<логин>.github.io/<репозиторий>/schedule.json` и убедитесь, что `for_date` — сегодняшняя дата.

## Workflows

- [`schedule.yml`](../.github/workflows/schedule.yml) — в 23:00 и 23:30 UTC (02:00 и 02:30 по Москве) прогоняет тесты, запускает `schedule_alarm.py` с секретами из таблицы выше и публикует `public/` на Pages. Второй запуск — повтор на случай, если портал ДГТУ не ответил.
- [`keepalive.yml`](../.github/workflows/keepalive.yml) — см. ниже.
- [`ci.yml`](../.github/workflows/ci.yml) — тесты Python и бота на push и pull request в `main`.

## Keepalive

В публичном репозитории GitHub отключает запуск по расписанию, если 60 дней не было активности. Для этого проекта это значит, что будильники перестанут обновляться посреди семестра.

`keepalive.yml` запускается 1-го числа каждого месяца и вызывает REST API:

```
PUT /repos/{owner}/{repo}/actions/workflows/schedule.yml/enable
PUT /repos/{owner}/{repo}/actions/workflows/keepalive.yml/enable
```

Нужно только право `actions: write` у встроенного `GITHUB_TOKEN`; коммитов и сторонних actions нет. Тот же приём использовал API-режим `gautamkrishnar/keepalive-workflow` v2, который применялся здесь раньше; сейчас этот action на GitHub недоступен.

Ограничение: в документации GitHub прямо не сказано, что повторное включение уже активного workflow сбрасывает счётчик 60 дней. На практике этот способ работает у многих проектов, но гарантии нет. Если GitHub всё же отключит расписание, он пришлёт письмо владельцу репозитория. Тогда:

1. Actions → Schedule Alarm Pages → **Enable workflow**.
2. То же для Keepalive Workflow.
3. Run workflow у Schedule Alarm Pages, чтобы сразу обновить `schedule.json`.

Любой коммит в `main` тоже считается активностью.

## config.json

```json
{
  "subgroup": 1,
  "prep_minutes": 90,
  "latest_alarm": "10:00",
  "slots": ["07:00", "08:45", "10:00"],
  "timezone": "Europe/Moscow",
  "exclude_keywords": ["русский язык как иностранный", "русский как иностранный", "рки"],
  "lessons_horizon_days": 28
}
```

| Параметр | Значение |
|---|---|
| `subgroup` | номер подгруппы. Пары без пометки подгруппы («п/г 1», «подгруппа 2» и т. п.) считаются общими и учитываются |
| `prep_minutes` | сколько минут нужно от будильника до начала первой пары |
| `latest_alarm` | будильник не ставится позже этого времени |
| `slots` | время будильников, созданных на iPhone (порядок не важен, скрипт сортирует) |
| `timezone` | часовой пояс расписания |
| `exclude_keywords` | пары, в названии которых есть одно из этих слов, игнорируются; сравнение без учёта регистра, последняя гласная ключевого слова отбрасывается, чтобы ловить падежные формы. Занятия по русскому как иностранному (РКИ) отсекаются всегда, даже если список пуст |
| `lessons_horizon_days` | на сколько дней вперёд пары отправляются боту |

Все параметры необязательны, значения по умолчанию в `schedule_alarm.py` совпадают с приведёнными выше. Если `config.json` не читается (например, ошибка в JSON), скрипт молча берёт значения по умолчанию — проверяйте строку «Конфигурация: …» в логе запуска.

## Расчёт слота

```
target = min(начало первой пары − prep_minutes, latest_alarm)
слот   = самый поздний из slots, который не позже target
```

| Первая пара | target | Слот |
|---|---|---|
| 08:30 | 07:00 | 07:00 |
| 09:00 | 07:30 | 07:00 |
| 10:15 | 08:45 | 08:45 |
| 12:00 и позже | 10:00 | 10:00 |
| 08:00 | 06:30 | 07:00 и предупреждение в `warning` |
| пар нет | — | `null`, все будильники выключаются |

## Локальный запуск

```bash
DONSTU_ICAL_URL='…' python3 schedule_alarm.py          # по сети
python3 schedule_alarm.py --file calendar.ics --today 2026-11-02 --output out/schedule.json
```

Параметры: `--file` — локальный `.ics` вместо загрузки, `--today` — подменить дату, `--output` — путь к JSON (по умолчанию `public/schedule.json`), `--config` — другой файл конфигурации. Файлы `*.ics` и `public/` в git не попадают.

## Если что-то сломалось

**Будильники не переключились, пришло «Расписание не обновилось».** Команда на iPhone сверяет `for_date` с текущей датой и при несовпадении ничего не меняет. Проверьте ночные запуски во вкладке Actions: чаще всего портал ДГТУ был недоступен. Запустите Schedule Alarm Pages вручную.

**Расписание перестало запускаться по ночам.** Вероятно, GitHub отключил его за неактивность — см. раздел «Keepalive».

**Портал ДГТУ блокирует запросы из GitHub Actions.** Скрипт завершится с ошибкой, деплой не произойдёт, и на Pages останется прежний `schedule.json` (с вчерашней `for_date`, поэтому iPhone ничего не изменит). Обходные пути: запускать `schedule_alarm.py` на домашнем компьютере или Raspberry Pi либо разбирать iCal прямо в быстрой команде, так как с российского мобильного интернета портал доступен.

**Бот не получил пары.** В логе шага «Fetch schedule and generate JSON» будет предупреждение с HTTP-кодом; будильники при этом всё равно публикуются. 401 — не совпадают `BOT_PUSH_TOKEN` и `PUSH_TOKEN`.
