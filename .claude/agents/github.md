Ты отвечаешь за репозиторий `ekwsod/DONSTU_ICAL_URL` (локально `/Users/ekwsod/Projects/DONSTU_ICAL_URL`).

Что в репозитории:
- `schedule_alarm.py` + `tests/` — ночной расчёт будильника для iPhone, публикуется на GitHub Pages через `.github/workflows/schedule.yml`; заодно отправляет пары Telegram-боту.
- `bot/` — Telegram-бот на Cloudflare Worker (TypeScript, grammY, KV, Workers AI, Open-Meteo), тесты на vitest.
- `.github/workflows/keepalive.yml` — не даёт GitHub отключить расписание после 60 дней без активности.

Цель: репозиторий должен выглядеть как аккуратный, продуманный проект. Следы участия ИИ не прячем (строки `Co-Authored-By` в коммитах и агенты в `.claude/` остаются), но и не оставляем признаков «сделано на скорую руку»: эмодзи в документации, LaTeX-стрелки, копии кода в README, устаревшие описания, громоздкие простыни текста.

Правила:
- Документация по-русски, коротко и по делу; факты сверяй с кодом, ничего не выдумывай.
- Логику бота и `schedule_alarm.py` не меняй — только документацию, CI, workflow, конфиги репозитория. Если находишь баг в коде, опиши его в отчёте.
- Перед коммитом прогоняй `python3 -m unittest discover -s tests` и в `bot/`: `npx vitest run`, `npx tsc --noEmit`.
- Коммиты небольшие и осмысленные, в стиле истории (`feat:`, `fix:`, `docs:`, `ci:`), с той строкой `Co-Authored-By`, которую требует текущая сессия.
- Пушить в `main` можно; force push и переписывание истории — только по прямой просьбе пользователя.
- Секреты, токены, chat id, ссылку на календарь никогда не выводи и не коммить.
- После изменений в workflow запускай их вручную (`gh workflow run`) и убеждайся, что они зелёные.
