# Telegram-бот

Личный бот с расписанием ДГТУ и домашними заданиями. Работает на Cloudflare Workers (TypeScript, [grammY](https://grammy.dev)) и отвечает только владельцу — сообщения из других чатов игнорируются.

## Возможности

Нижнее меню в две строки: «Сегодня», «Мои дз», «Завтра» и «Записать дз», «Настройки».

- **День** — главный экран. Сверху погода (сводка на день и к первой паре), затем каждая пара отдельным блоком: номер, время, предмет, тип, корпус и аудитория, домашнее задание к ней. Внизу погода после пар. Между днями — стрелки, у каждой пары кнопка добавления дз.
- **Недели** — кнопка «К неделе» в экране дня или `/week`: текущая и три следующие. В неделе по кнопке на день с числом пар, дз и погодой.
- **План перед выходом** — в дни с парами за заданное время до первой пары (по умолчанию 60 минут) бот присылает погоду, пары по порядку с аудиториями, окна между ними, что сдать, когда всё закончится и погоду после пар. В конце — короткий комментарий модели.
- **Напоминание о дз** — накануне срока (по умолчанию в 20:00) список того, что сдавать завтра.
- **Дз своими словами** — «Записать дз», кнопка под списком «Мои дз» или `/new` показывают пример, и следующее сообщение разбирает модель: например, «матан к пятнице 1–5 и конспект §3». Бот находит предмет в расписании, срок и пункты и показывает карточку: сохранить, другой срок, другой предмет, отмена.
- **Дз к паре** — кнопка у пары, затем текст и срок: к следующей паре, к следующей лекции или выбранная дата. `/cancel` отменяет ввод.
- **Мои дз** (`/hw`) — открытые задания; в карточке можно отметить выполненным, удалить или открыть день сдачи.
- **Настройки** (`/settings`) — режим срока дз (спрашивать, к следующей паре, к следующей лекции), за сколько минут до пары присылать план (выкл., 30, 45, 60, 90), во сколько напоминать о дз (выкл., 18, 20, 22 часа). Там же кнопка примера плана.
- **Пример плана** (`/plan`) — сразу присылает план перед выходом на ближайший день с парами, такой же, как утром; утреннюю отправку не отменяет.

## Архитектура

- **Расписание.** Бот сам iCal не скачивает. Ночной workflow `schedule.yml` после расчёта будильника отправляет пары на 28 дней (`lessons_horizon_days` в `config.json`) запросом `POST /push` с заголовком `Authorization: Bearer <PUSH_TOKEN>`. Worker сохраняет их в KV. На публичные Pages полный список пар не попадает.
- **Telegram.** Обновления приходят на `POST /webhook`; grammY проверяет заголовок `X-Telegram-Bot-Api-Secret-Token` по `WEBHOOK_SECRET`. Остальные пути отвечают 404.
- **Хранилище.** Cloudflare KV, привязка `SCHEDULE`. Пользователь один, поэтому каждая сущность — один JSON-ключ: пары, дз, настройки, незаконченный ввод, кеш погоды, отметки об отправленных сообщениях.
- **Cron Trigger** `*/5 * * * *` — раз в пять минут проверяет, не пора ли отправить план перед выходом или напоминание о дз. Время в cron — UTC, решение принимается по московскому времени; каждое сообщение отправляется не чаще раза в день.
- **Погода** — [Open-Meteo](https://open-meteo.com), бесплатно и без ключа. Координаты главного корпуса заданы в `wrangler.toml` (`WEATHER_LAT`, `WEATHER_LON`), прогноз кешируется в KV на час.
- **Модель** — Workers AI (привязка `AI`), `@cf/meta/llama-3.3-70b-instruct-fp8-fast`: бесплатна на тарифе Workers Free и отвечает примерно за 2 секунды. Модели DeepSeek V4 на бесплатном тарифе недоступны, а бесплатный DeepSeek R1 Distill отвечает 8–12 секунд и не выдаёт корректный JSON для разбора дз. Модель меняется константой `AI_MODEL` в `src/ai.ts`.

  Модель используется для двух вещей: комментарий в конце плана дня и разбор дз из свободного текста. Время, аудитории и даты считает код, ответы модели проверяются: предмет принимается только из списка в расписании, дата — только после сегодняшней и не позже последнего загруженного дня. Если модель не ответила за 12 секунд или вернула ошибку, бот работает без неё: план приходит без комментария, а для дз предлагается выбрать предмет кнопками.

## Секреты

| Где | Имя | Что это |
|---|---|---|
| Cloudflare (`wrangler secret put`) | `BOT_TOKEN` | токен от @BotFather |
| Cloudflare | `OWNER_CHAT_ID` | chat id владельца; остальным бот не отвечает |
| Cloudflare | `WEBHOOK_SECRET` | случайная строка, Telegram присылает её с каждым обновлением |
| Cloudflare | `PUSH_TOKEN` | случайная строка для `/push` |
| GitHub Actions | `BOT_PUSH_URL` | `https://<worker>.workers.dev/push` |
| GitHub Actions | `BOT_PUSH_TOKEN` | то же значение, что `PUSH_TOKEN` |

## Деплой с нуля

Нужен Node.js 22.12 или новее. Команды выполняются в папке `bot/`.

```bash
npm ci
npx wrangler login
npx wrangler kv namespace create SCHEDULE   # полученный id вписать в wrangler.toml
npx wrangler secret put BOT_TOKEN           # так же OWNER_CHAT_ID, WEBHOOK_SECRET, PUSH_TOKEN
npx wrangler deploy
```

Привязка webhook (токен и секрет вводятся без отображения и не попадают в историю shell):

```bash
read -s T; read -s S
curl -s "https://api.telegram.org/bot$T/setWebhook" \
  -d "url=https://<worker>.workers.dev/webhook" -d "secret_token=$S"
unset T S
```

Затем добавьте `BOT_PUSH_URL` и `BOT_PUSH_TOKEN` в секреты GitHub и запустите workflow Schedule Alarm Pages вручную — после этого в боте появятся пары. Отправьте боту `/start`, чтобы получить меню.

## Тесты

```bash
npx tsc --noEmit
npx vitest run
```

Покрыты сроки дз, поиск следующей пары, тексты и клавиатуры, план перед выходом, погода и разбор ответов модели (с подставной моделью, без сети). Те же проверки запускает CI.
